# Apache Polaris local dry-run — catalog governance feasibility (H-CATALOG-AUDITABILITY-01 §10)

A rehearsal to de-risk the Q3 catalog commitment before AWS dollars — **never the Tier-A result**. Stood up
Apache **Polaris 1.5.0** (the already-pulled `apache/polaris:latest`, Quarkus) on the docker substrate with
in-memory persistence + non-interactive bootstrap, and exercised the governance surface H-CATALOG-AUDITABILITY-01
rests on (RBAC + audit trail). Tier B, single host, dev config.

## What stood up + worked

- **Deployable on the docker substrate:** `docker run apache/polaris:latest` with
  `POLARIS_BOOTSTRAP_CREDENTIALS` + `POLARIS_PERSISTENCE_TYPE=in-memory` → **healthy in ~9 s**, realm
  bootstrapped, Iceberg REST catalog on :8181, Quarkus management (health/metrics) on :8182.
- **OAuth2 + management API:** client-credentials token (root principal) → `/api/management/v1/*` works
  (note: the Polaris management API is on the main port **:8181**, not the Quarkus management port :8182).
- **RBAC works end-to-end:** created principal `soc_analyst` (server-issued clientId), principal-role
  `readonly_hunters` (201), assigned the role to the principal (201), verified `principals=[root,
  soc_analyst]` and `soc_analyst.roles=[readonly_hunters]`. The role/grant model the audit-trail compliance
  story needs is present and functional.
- **Entity-level audit metadata out of the box:** every catalog object carries `createTimestamp`,
  `lastUpdateTimestamp`, and `entityVersion` (seen on the `soc_analyst` create response) — a baseline
  who/when/version audit trail at the entity level, the immutable-history property a mutable SIEM index
  can't give.

## Two honest findings (the rehearsal's value)

1. **FILE storage is unsupported for catalogs in 1.5.0** (`"Unsupported storage type: FILE"`, HTTP 400) — a
   catalog needs S3/GCS/Azure storage. So the *data-plane* dry-run (create catalog → namespace → table →
   table-level RBAC at 10k–1M rows) needs an **object store + S3 storage config** (MinIO is on-host; Polaris
   S3 typically expects STS-style credentials, so the MinIO integration is the next friction to work). The
   control-plane (RBAC + principals + audit metadata) was fully exercisable *without* storage.
2. **Structured audit-EVENT logging / forwarding is not default-on.** The hypothesis names "event log
   persistence forwarding catalog operations to JDBC and CloudWatch" — that is a **configurable feature**
   (consistent with the hypothesis's BETA status), not emitted to stdout in the dev config (a grep of the
   server logs for the RBAC operations found no structured audit events). The baseline audit trail you get
   for free is the **entity metadata** (timestamps + versions); the operation-level event-log forwarding
   must be explicitly configured — a real consideration for the Q3 compliance commitment.

## What it does to the hypothesis

Corroborates H-CATALOG-AUDITABILITY-01 first-hand at the feasibility level: Polaris **is deployable** on the
docker substrate and the governance surface (RBAC + entity-level audit metadata) **is present and works**;
the operation-level event-log persistence (JDBC/CloudWatch forwarding) is a **configurable beta feature, not
default-on** — matching the hypothesis's "BETA, schema may change" framing. This is a control-plane rehearsal;
the **full data-plane dry-run (catalog-on-object-store + table-RBAC + audit-event forwarding at 10k–1M rows)
remains the next step** and needs S3 storage + the event-log-persistence config. Stays a rehearsal, never the
Tier-A result.

## Reproduce

```
docker run -d --name polaris-dryrun -p 8181:8181 -p 8182:8182 \
  -e POLARIS_BOOTSTRAP_CREDENTIALS=POLARIS,root,s3cr3t -e POLARIS_PERSISTENCE_TYPE=in-memory \
  -e quarkus.otel.sdk.disabled=true apache/polaris:latest
# token: POST :8181/api/catalog/v1/oauth/tokens  grant_type=client_credentials client_id=root client_secret=s3cr3t scope=PRINCIPAL_ROLE:ALL
# RBAC: POST :8181/api/management/v1/principals | /principal-roles | PUT /principals/{n}/principal-roles
```

## Caveats (Tier B)

Single host, dev config (in-memory persistence — the server itself warns it's test-only), Polaris 1.5.0.
Control-plane (RBAC + audit metadata) exercised; data-plane (catalog-on-S3 + table-RBAC + audit-event
forwarding at scale) not — that is the owed full dry-run. A rehearsal to confirm deployability + surface,
not a governance benchmark.
