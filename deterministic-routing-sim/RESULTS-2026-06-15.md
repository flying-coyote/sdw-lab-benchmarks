# deterministic-routing-sim — results (2026-06-15)

First measured test of **H-DETERMINISTIC-ROUTING-01** (the hypothesis was PROPOSED/gated-pending with
"the routing simulation has not run"). This is a **routing-decision simulation**, not a live
multi-engine measurement: it checks the deterministic router's ENGINE PICK against the recorded
per-(shape, tier) winners from `engine-join-specialization/results/RESULTS.md` (single host,
2026-06-10), then stresses the router with the five production misrouting modes Gemini DR-5 named
(2026-06-15). Tier **B- / simulation**. Tool: `sqlglot 30.11.0`, lab-free (no engines).

## The rules (as implemented)

Ordered, auditable, no LLM, no per-query engine probing:
- **R1 time tier** — extract a static time boundary; compare to now; window ≤ 7 days → hot
  (native MergeTree eligible), else → cold (Iceberg engines). A function-wrapped or dynamic
  (`NOW()`) time predicate is not statically evaluable → safe default = cold/lakehouse tier.
- **R2 shape** — classify the AST (join count, agg, correlated EXISTS, top-N, point-lookup) →
  the measured per-shape winner for the decided tier.
- **R3 catalog consult** — resolve views to their true underlying shape + read Iceberg manifest
  scan stats. This is the step DR-5 says a generic AST router skips.

## What this says about the hypothesis

**Supports it, on the scoped denominator.** The ordered rules assign 100% of the templated SOC
shapes to the measured winner, so "≥90% of SOC-shaped queries" holds *for templated, time-bounded
traffic* — which is the traffic the hypothesis (and the production survivors) target. The residual
misroutes are all in-spread (the SOC joins all answer 0.07–1.41 s), as predicted.

**But the ≥90% is partly circular and must be stated that way.** The ground-truth winner map is a
~10-shape lookup table from one host; the templated corpus IS those shapes. So 100% means "the rules
correctly encode the table," not "routing is solved." This is exactly DR-5's point: the ≥90% seen in
production (Uber/Netflix/Trino-Gateway) is a **denominator artifact** of templated automated traffic
(90–95% of real traffic), not router intelligence. The falsifiable contribution here is the
**per-mode degradation**, not the headline.

**Two sharpenings of the hypothesis's own framing:**
1. **The catastrophic class is closed by catalog/view resolution, not by manifest row counts.** The
   only catastrophic path is a *misclassified* shape that routes to the native cliff; the
   view-obfuscation mode triggers it, and consulting the catalog (resolving the view to its true
   shape) closes it completely (1.0 vs 0.0). The hypothesis's "manifest statistics as the cost
   signal" is right in spirit but should be stated as **"consult the catalog before routing"** — the
   load-bearing part is *semantic resolution*, which DR-5 names as the thing AST routers skip.
2. **The q5 native cliff is a join-cardinality explosion that manifest SCAN stats cannot predict.**
   q5 DNFs on native; q9 (also 6-table, near-identical scan size) completes — so a raw scan-row
   threshold can't separate them (it false-positived q18, a 3-table agg native handles in 1.19 s).
   The cliff is avoided **structurally** (the shape→winner map never routes a join-heavy shape to
   native), not by row counts. "Manifest stats catch the cliff" is too strong; manifest stats catch
   *hidden-scan-size* cliffs (view obfuscation), shape catches *join-cardinality* cliffs.

**The primary key is the soft spot.** Time-predicate masking (mode 2) degrades R1 — the hypothesis's
first and most-relied-on rule — to a minor misroute. SPL-generated SQL via DB Connect "nearly always
carries time bounds" (the hypothesis's mitigation), but analyst ad-hoc queries that wrap the time
column will tier-flip. Worth a normalization pass (unwrap common `CAST`/`date_trunc(time)` idioms)
before R1, as a cheap hardening.

## Limitations (owed before any confidence move)

- Engine-routing only — does NOT model intra-engine resource/queue cost, so the skew mode (3) is
  understated (scored "correct" because the engine is right; the resource harm is invisible here).
- One host, ~10-shape ground truth, n=1 per mode (one query per failure mode) — the per-mode numbers
  are demonstrations of the *mechanism*, not rates. A rate would need many queries per mode.
- Dynamic-functions mode tested only on the deep-history case (where the safe fallback is correct);
  the dynamic-recent case is untested.
- Dremio dialect proxied as trino/presto in sqlglot (no native dremio dialect).
- The ground-truth winners are themselves Tier-B single-host (the join bench) — the circularity is
  structural, not removable without a second independent host or workload.
