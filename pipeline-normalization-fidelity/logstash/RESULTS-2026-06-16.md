# Logstash two-edition arm — both editions ship NO native OCSF mapping (2026-06-16)

The Logstash arm of pipeline-normalization-fidelity (#10), H-PIPELINE-OCSF-FIDELITY-01. Pre-registered
(`gemini-20260616-pipeline-tier-dewitt-reconciliation.md` §3): bench **both editions** — the OSS/Apache build
vs the Elastic-distribution binary — and let the measured delta decide whether "Logstash" is one tool or two,
with the Elastic distribution DeWitt-locked (Elastic Software EULA §1.3(v)) and the OSS build nameable.
`logstash/run_logstash_arm.sh`. Tier B, single host, synthetic corpus (the shared 4-source gold).

## What was run

- **Editions:** OSS = `logstash-oss:7.10.2` (the last Apache-2.0 OSS Logstash, before the 7.11 relicense);
  Elastic distribution = `logstash:8.17.0` (Elastic License 2.0).
- **STEP 1 — shipped-plugin availability** (the P1 question): `logstash-plugin list` on each edition. Both
  ship `logstash-codec-cef` (CEF) and **no `ocsf` codec or filter** — there is no native OCSF normalization
  in either edition. (OCSF in the Elastic world lives in Fleet/Agent integrations, not Logstash core.)
- **STEP 2 — passthrough run + score:** 200 zeek_conn records through each edition with the only available
  path (`stdin json_lines → stdout json_lines`; there is no OCSF codec to invoke). Both editions emitted the
  records carrying **zero OCSF fields** (no `class_uid` / `activity_id` / `type_uid`), then scored with the
  shared instrument across all four sources.

## Result — identical, 0% both editions

| edition | zeek_conn | cloudtrail | sysmon | auth |
|---|---|---|---|---|
| **logstash_oss** (7.10.2) | 0% cov/field/value/class/act | 0% | 0% | 0% |
| **logstash_elastic** (8.17.0) | 0% cov/field/value/class/act | 0% | 0% | 0% |

The two editions are **identical** (both 0% everywhere). Per the pre-registered decision rule (identical
emitted-fidelity within ~20% → one "Logstash"), this is **ONE tool**, not two.

## What it says

Logstash, like Vector, ships **no native OCSF normalization** — "maps to OCSF" is not a capability it has
out of the box in either edition; producing OCSF requires a hand-written filter pipeline (which is the user
building the mapping, not the tool shipping it). This is the **availability finding** the bench's P1 names —
now confirmed across a **third** tool:

| tool | shipped OCSF coverage |
|---|---|
| Tenzir | 1 of 4 sources (zeek_conn maps; cloudtrail/sysmon/auth = 0) |
| Vector | 0 of 4 (no OCSF component) |
| **Logstash (both editions)** | **0 of 4 (no OCSF codec/filter)** |

So availability — does the tool ship a mapping at all — is the binding constraint before fidelity even
enters the picture, on three of the open-pipeline tools tested.

## DeWitt treatment — moot

The pre-registration prepared to DeWitt-lock the Elastic-distribution arm if it produced a publishable
performance result. It did not: a **0%-availability finding is a capability statement** ("ships no OCSF
mapping"), not a benchmark performance number, so the Elastic Software EULA §1.3(v) benchmark-publication
clause is **not triggered** — both editions are nameable, nothing to genericize. (If a future Logstash version
ships an OCSF mapping and this becomes a fidelity *score*, re-apply the two-edition DeWitt rule.)

## Caveats (Tier B)

- Availability/capability finding, scored 0 by the same instrument as the Vector arm — not a fidelity
  measurement (there is nothing to measure when no mapping ships).
- The passthrough run is the demonstration that Logstash executes and emits non-OCSF; the load-bearing fact
  is the plugin-list availability (verified from both editions).
- Version-bound: logstash-oss 7.10.2 / logstash 8.17.0, 2026-06-16. Synthetic corpus, single host.

## What it does to the hypothesis

Adds a third availability-zero to H-PIPELINE-OCSF-FIDELITY-01's basis (Tenzir 1/4, Vector 0/4, Logstash 0/4).
**Stays 2.5/5 gated-pending** — the gate is "until Cribl + Vector score," and Cribl (the one tool that ships
a packaged OCSF Pack — the falsifying test for the broad cross-vendor "low fidelity" claim) is still unrun
(needs a Cribl Stream Free account). Logstash strengthens the availability leg; it does not un-gate the broad
claim. Route karen → hypothesis-validator → contradiction-detector; expected disposition HOLD-gated.
