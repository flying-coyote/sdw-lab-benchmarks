# Cribl OCSF arm — the richest pipeline OCSF path, but source-specific + coverage-incomplete (2026-06-16)

The Cribl arm of pipeline-normalization-fidelity (#10), H-PIPELINE-OCSF-FIDELITY-01 — the falsifying test
(Cribl is the one tool advertised as shipping packaged OCSF). Run **via Docker, no account**: `cribl/cribl`
4.18.1 free on-prem, the **`cribl pipe`** CLI (feed stdin → a pack pipeline, headless — no UI/API/login), with
the public community pack **`camrunr/cribl-ocsf-conversion` v0.5.1** (GitHub, "work in progress, use with
caution"). Tier B, single host. Cribl is DeWitt-CLEARED (publishable named).

## What ships where (the availability picture — confirms the owner's in-tool finding)

- **Cribl base image ships NO OCSF** out of the box (no bundled OCSF pack/function) — like Vector/Logstash.
- Cribl's OCSF is delivered by **source/partner-specific packs, not a universal "OCSF Pack":** searching
  "OCSF" inside the tool's Dispensary surfaces **AlphaSOC** network-detection mappings (a detection partner —
  cribl.io/resources/sb/alphasoc-and-cribl/); the **Amazon Security Lake** pack covers AWS sources; this
  **community camrunr pack** covers Okta / AWS WAF / Proofpoint TAP. There is no one pack that normalizes
  arbitrary sources to OCSF — availability is per-source/per-partner.
- None of the public packs covers the bench's 4-source corpus (zeek_conn / cloudtrail / sysmon / auth)
  directly; the AWS-CloudTrail→OCSF path is the official Dispensary Security Lake pack (account-gated).

## Result — 3 conversions, the pack's own samples (NOT the bench corpus)

| conversion | class_uid | category | type_uid | activity_id | mapped attrs | unmapped groups |
|---|---|---|---|---|---|---|
| Okta system-auth → **3002** | ✓ 3002 | ✓ 3 | ✓ 300299 | **99 (Other — degraded)** | 17 | 10 |
| AWS WAF → **4002** | ✓ 4002 | ✓ 4 | ✓ 400203 | ✓ 3 (classified) | 21 | 4 |
| Proofpoint TAP → **4009** | ✓ 4009 | ✓ 4 | ✓ 400903 | ✓ 3 (classified) | 12 | 8 |

All three emit **structurally-valid OCSF with the correct class / category / type_uid**, with rich core
mapping (e.g. Okta→3002 lands `user`, `src_endpoint` with ip/geo/ASN, `http_request`, `dst_endpoint`,
`status`, `severity_id`, `time`). **Two of three classify the activity**; Okta degrades to `activity_id: 99`
(Other) — the OAuth-authorize event wasn't resolved to a specific Authentication activity. Every conversion
leaves a **real unmapped tail** (4–10 field groups parked in `unmapped.extras`).

## What it says (and where it leaves the hypothesis)

Cribl is the **best OCSF emitter of the pipeline tools tested** — Tenzir was class-right / 17% activity / 0%
on 3 of 4 sources; Vector and Logstash ship nothing; Cribl actually produces valid OCSF with correct class
and mostly-correct activity. That **tempers** the strong "pipelines emit unusable OCSF" reading: with a pack
for the source, Cribl emits high-fidelity-*ish* OCSF.

But the bench's core thesis **holds even here**: (1) availability is still the binding constraint — it's
source/partner-specific, no universal pack, and nothing public covers the bench corpus; (2) "maps to OCSF" is
**coverage, not complete fidelity** — correct class, but activity-classification is rule-dependent (1 of 3
degraded to Other) and a meaningful unmapped tail remains. So the same correct-class / partial-activity /
incomplete-coverage pattern as Tenzir, on the richest OCSF path.

## Caveats (Tier B) — why this is not yet the clean gate-clearer

- **Community pack** (`camrunr` v0.5.1, self-labeled WIP), **not the official Dispensary pack**, run on the
  **pack's own bundled samples**, **not the bench 4-source corpus/gold** — so it is **not apples-to-apples**
  with the Tenzir/Vector/Logstash arms (which ran the shared corpus through `score.py`). The fidelity here is
  assessed intrinsically (class/type correctness, activity classification, mapped-vs-unmapped), not against
  the bench gold.
- **Non-SaaS scope (owner 2026-06-16):** the official AWS-CloudTrail→OCSF (Amazon Security Lake) pack is
  **not** pursued as the clearer — Amazon Security Lake is an AWS-SaaS OCSF lake, off SDW's non-SaaS /
  self-hostable thesis, so it adds no value here. This on-prem run (Docker, no account, no SaaS) is the
  thesis-aligned measurement; no public on-prem Cribl pack covers the bench corpus sources, so the pipeline-
  tool fidelity arm is at its on-prem evidential ceiling.
- Single host, Cribl 4.18.1, pack v0.5.1, version-bound.

## What it does to the hypothesis

First **measured** Cribl OCSF fidelity (3 conversions), via Docker, no account. **Gate disposition: HOLD
