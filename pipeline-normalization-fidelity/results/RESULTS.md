## Erratum (appended by hand 2026-11-15; not produced by score.py)

This file is generated by `score.py`. A later `score.py` run without `--no-write` or a different `--results-dir` will overwrite it and drop this erratum, so re-append it or write to another directory.

The zeek_conn numbers above (field 80%, value 92%, activity_id 17%) are what the frozen scorer computes, but the "Where the fidelity went" lines misdescribe the mechanism. Re-derived over all 100,000 records on 2026-11-15 (`../../ocsf-1.9-rescore/scripts/erratum_derive.py`, output `../../ocsf-1.9-rescore/results/erratum-derivation.json`; full text in `../FINDINGS-2026-06-14.md`, "Erratum"):

- `activity_id` 17%: the gold pins `activity_id = 6` on every record (`gen_corpus.py` l.180-181); Tenzir derives it from `conn_state` (S0→1, SF→2, RSTO/RSTR→3, REJ→5, OTH→6) and agrees with the gold only on OTH (16,702 records). Not a failure to derive activity.
- `history`, `service`, `uid` "dropped": not in `unmapped` (which holds only the bench's `_id` on every record). They landed on `connection_info.flag_history`, `app_protocol_name` and `connection_info.uid` / `metadata.original_event_uid` / `metadata.correlation_uid`, each with the source value on 100,000 records and each resolving "full" in the 1.8.0 subset. The scorer credits only the gold's path.
- `ts`×100000: a type-contract deviation (RFC 3339 string where `timestamp_t` requires epoch-ms long). The value survives at the corpus's microsecond precision on every record.
- `duration`×53: every one is an exact half-millisecond tie; the gold rounds half to even, Tenzir rounds half up.

Corrected numbers are not stated here; they come from the pre-registered re-score in `../../ocsf-1.9-rescore/`.
