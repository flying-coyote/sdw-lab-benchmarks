# R11 pre-registration: inference cost per alert and per triage at right-sized models

Frozen by agent before any run; not owner-reviewed. Nothing here has been executed. The sha256 at freeze is
in `README.md`. Source request: `SITE-REVIEW-2026-11-09.md` section 5, row R11, which notes that no
first-party cost data exists and asks for a bench pairing `ocsf-nl2sql-silenterror` / `ocsf-airgap-agent`
accuracy with measured cost per task, publishing to the economics pages only once measured.

## Question

What does it cost, in tokens and dollars, for a model to triage one alert or answer one analyst question
over an OCSF store, and what is the cheapest model and effort setting whose accuracy stays within a fixed
margin of the best arm? The quantity of interest is cost per correct answer, not cost per request, because
a cheaper request that is wrong or needs more steps is not cheaper.

## Definition fixed before the run

**Right-sized arm**: the lowest-cost arm (by mean USD per correct answer) whose accuracy on every stratum
is within 5 points of the best arm on that stratum, and whose silent-error rate is no more than 5 points
above the best arm's. Accuracy is balanced accuracy for triage and result accuracy for NL2SQL. If no
cheaper arm meets both conditions, the best arm is the right-sized arm, and that is the result.

## Instrument

Three task families, two of them new runs and one reusing R3's traces:

1. **NL2SQL (single-shot)**: the 33 labeled questions across 7 difficulty tiers in
   `ocsf-nl2sql-silenterror/questions.py`, over the testbed Store F, scored by the existing scorer into
   correct / silent / loud. Existing local results (phi3:latest result accuracy 0.36, silent-error rate
   0.09; `ocsf-nl2sql-silenterror/results/RESULTS.md`) are the precedent; this run adds hosted arms, repeated
   trials and cost.
2. **Alert triage (short agent loop)**: 100 alerts, 25 true positive and 75 false positive, drawn with seed
   20261109 from the testbed Store F before the run and frozen with a logical fingerprint. True positives
   are malicious-labeled rows from the planted six-stage chain (the corpus manifest counts 94 malicious
   rows across api, dns, network and process), sampled across stages; false positives are benign rows that
   match the `ocsf-attack-coverage` rules or console detections, including the T1021 rule's 2,959 benign
   matches. Each alert is presented as the matched row plus rule name; the model may run up to 4 read-only
   SQL steps and must return JSON with `verdict` (true or false positive) and the evidence uids it relied
   on. Labels come from the ground truth (fingerprint `46af223bf406…`), never from a model.
3. **Agentic hunt (reused)**: R3's hosted-arm episodes, priced from their logged `usage`. No new spend; if
   R3 has not run, this family is reported as not available rather than estimated.

## Arms

| arm | model | effort / settings | served version |
| --- | --- | --- | --- |

| H-opus-low, H-opus-med | Claude Opus 5.5 (`claude-opus-5-5`) | effort low, medium (thinking cannot be disabled on this model; effort is the only control) | same |
| L-e4b | gemma4:e4b | Ollama default temperature, recorded | Ollama 0.20.6, digest `c6eb396dbd59` |

| L-phi4 | phi4:latest | same | digest `ac896e5b8b34` |

Haiku 4.5 ($1 / $5 per million tokens) is excluded because Haiku 5.5 is the current small tier at a tenth
of the price; including the older model would only measure a pricing generation. Prompt caching is on for
hosted arms (system prompt and schema cached), because that is how a production triage loop would run;
the uncached counterfactual is computed from the same `usage` fields, so no extra calls are needed. Prompts
are frozen and hashed before the pilot, no tuning, and any post-pilot change is an amendment re-run on a
second model before a lift is claimed (methodology §10).

## Metrics

- **Tokens per task**: input, cache-read, cache-write and output, from the API `usage` object.
- **USD per task** and **USD per correct answer**, at list price; also **USD per 1,000 alerts** for triage,
  as plain arithmetic from the per-alert mean, labelled an extrapolation.
- **Input share of cost**: input-side dollars (including cache reads and writes) over total dollars.
- **Accuracy**: balanced accuracy and per-class recall for triage; correct / silent / loud rates for NL2SQL.
- **Verdict flip rate** per (arm, item) beside every mean (methodology §10).
- **Wall-clock per task** with monotonic timers (reported with the §7b rig stamp, not used for USD on
  hosted arms).
- **Local USD**, declared formula, Tier D because there is no power meter on this host:
  `wall_hours x (watts / 1000 x tariff_usd_per_kwh) + wall_hours x amortization_usd_per_hour`, with
  watts = 65 (a whole-box estimate for a 45 W TDP Ryzen 7 5800H mini PC, not measured), tariff = $0.15 per
  kWh placeholder, and amortization = purchase price / (3 years x 8,760 hours). Jeremy supplies the real
  tariff and purchase price before the run; the result is reported as a band at 0.5x and 2x of the point
  estimate. If a wall-plug meter becomes available, measured watts replace the estimate and the tier
  improves.

Every metric is reported per task family and per stratum (NL2SQL tier; triage technique and TP/FP class)
before any pooled figure. Intervals: Wilson 95% for rates; bootstrap 95% (10,000 resamples, seed 20261109)
for USD-per-correct ratios.

## Hypotheses and what would prove each wrong

- **H1, a much cheaper arm is good enough for triage.** The right-sized triage arm costs at most 10% of
  the best arm's USD per correct answer. Wrong if the right-sized arm costs more than 10%, including the
  case where the best arm is the only one within margin.
- **H2, effort is the cheapest lever.** On at least one hosted model, effort low versus medium cuts USD per
  correct triage by at least 30% while changing balanced accuracy by no more than 5 points. Wrong if no
  hosted model meets both.
- **H3, evidence dominates the bill.** On agentic triage, input-side dollars are at least 60% of billed
  dollars for every hosted arm. Wrong for an arm if the share is under 60%.
- **H4, the silent-error band moves with model size.** The NL2SQL silent-error rate on the mid-difficulty
  tiers (group_by, time_window, multi_condition, join) is not lower for the cheapest hosted arm than for
  the most expensive one. Wrong if the cheapest arm's silent rate is lower by more than the interval
  overlap allows (bootstrap 95% interval of the difference excludes zero in the cheap arm's favour).
- **H5, local is not free (Tier D).** Under the declared local cost formula, gemma4:26b's USD per correct
  triage exceeds Haiku 5.5's at its right-sized effort. Wrong if it is lower across the whole 0.5x to 2x
  band. This is labelled Tier D whatever the outcome, because the watts are estimated.

## Run count

- NL2SQL: 33 questions x 8 trials = 264 episodes per arm; 6 hosted arms and 3 local arms.
- Triage: 100 alerts x 5 trials = 500 episodes per arm; same 9 arms. Five trials rather than eight keeps
  Opus spend bounded; the flip rate is still computable.
- Pilot: 5 alerts and 5 questions x 2 trials per arm, excluded from results, to measure real token counts
  against the estimate below.

## Cost estimate

List prices from the claude-api skill model table, cached 2026-10-06 (vendor documentation, Tier B for
price): Haiku 5.5 $0.10 / $0.50 per million input / output tokens (prompts under 100k tokens), Sonnet 5.5
$2 / $10, Opus 5.5 $4 / $20. Re-check at run time. Estimates are uncached, which overstates.

Token model, to be replaced by the pilot: one NL2SQL question is about 2.5k input (schema plus question)
and 1k output including thinking; one triage episode is about 4 steps, roughly 4 x 1.5k + 2.6k x 6 ≈ 21.6k
input and 2k output.

| model | per NL2SQL question | 264 x 2 efforts | per triage | 500 x 2 efforts | model total |
| --- | --: | --: | --: | --: | --: |
| Haiku 5.5 | $0.00075 | $0.40 | $0.0032 | $3.2 | ~$3.6 |
| Sonnet 5.5 | $0.015 | $7.9 | $0.063 | $63 | ~$71 |
| Opus 5.5 | $0.030 | $15.8 | $0.126 | $126 | ~$142 |

**Expected about $217, ceiling about $325 with 1.5x contingency.** Low effort spends fewer output tokens
than this model assumes, so the true figure is likely lower. Two cheaper tiers, if the owner wants them:

- Drop Opus 5.5: about $75 expected, $112 ceiling.
- Run NL2SQL through the Message Batches API (50% off, single-shot fits it): saves about $12.

Agentic-hunt family: $0 new spend (priced from R3 traces).

Local compute, $0 API: triage at about 4 steps x 34 s ≈ 2.3 min per episode is about 19 hours per local
model for 500 episodes (gemma4:26b guessed at 1.5x, about 28 hours, no measured baseline); NL2SQL about 3
hours per local model. **About 75 hours serial for the three local arms.** Build and write-up: alert draw
and triage harness about 6 to 8 hours, cost ledger about 2 hours, write-up about 4 hours.

## Stop rule

- Hard spend cap **$330**, tracked from `usage` after every call; at the cap the run stops and reports
  completed cells as N-of-M. Opus arms run last so a cap hit loses the most expensive cells first.
- If the pilot projects more than 1.5x the estimate, pause for owner sign-off before the main run.
- No arm is stopped early on a favourable result.

## Limits declared up front

- List price is not what every buyer pays; enterprise discounts, cloud-marketplace pricing and Bedrock or
  Vertex rates differ, so USD here is list-price USD on the first-party API.
- The triage set is synthetic with a fixed 1:3 TP:FP ratio; production base rates are far more skewed (run
  1's T1021 rule had 1 true positive in 2,960 matches), so USD per 1,000 alerts at a realistic base rate is
  arithmetic on these per-alert costs, not a measurement.
- Local USD is Tier D until watts are measured.
- One harness and one prompt format; a different harness could move both accuracy and tokens (the Dye
  observation in methodology §10).
- Testbed Store F is synthetic and may be recognizable as such; R3's probe covers this for the same corpus.
