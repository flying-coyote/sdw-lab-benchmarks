# BENCH-C v2 results — OBDA vs probabilistic vs structured-query over OCSF, three model tiers

**2026-06-17. Tier B, single host, synthetic Store F corpus + the A9 12-asset overlay. Directional pilot — the *order/mode of failure* is the transferable claim, not the magnitudes.** Pre-registered in `BENCH-C-PREREGISTRATION-v2-rerun.md` + `-v2-ADDENDUM-impl-decisions.md`; run after the v1 confounds (A4 gold-anchor, A9 2-asset freebie, lookup retrieval, missing structured-query channel) were removed. Six arms, shared byte-identical scorer (`scoring.classify`), 8 trials per LLM cell, A4 excluded as ill-posed. The LLM-generation arms were run at **three model tiers — Haiku, Sonnet, Opus — with the model held constant across arms within a tier** (mixing tiers within the head-to-head would confound method with model).

## Headline

On the **compute-over-population tail** (A3 cross-source ordering, A7 dwell-time, A9 distinct-asset count), **no LLM arm at any tier ever produced the correct answer.** The only correct tail answer anywhere came from the **human-curated metrics layer** (A9). What separates the arms is not correctness — it is the **failure mode**, and the central finding is that the failure mode of the LLM-authored structured-query path **inverts with model capability**:

- The **probabilistic paths fail silently at every tier.** Text-to-SQL is silently wrong on the tail at 0.54 (Haiku) / 0.625 (Sonnet) / 0.50 (Opus); GraphRAG is silently wrong 1.0 at all three tiers. A frontier model is still silently wrong about half the time.
- The **LLM-authored SPARQL path (structured-graph-query) flips from loud to silent as the model gets better.** Haiku and Sonnet fail **loud** (1.0 / 0.96 — they write malformed aggregations that Ontop rejects); **Opus fails silent (0.96)** — it writes clean, minimal, *executable* SPARQL that runs and returns a wrong answer. Verified on the actual queries: for A9, Haiku/Sonnet emitted `COUNT(DISTINCT …)` over complex `UNION`/`GROUP BY` patterns that Ontop refuses, while Opus emitted `SELECT (COUNT(DISTINCT ?host)) WHERE { ?s :host ?host }`, which executes and returns the wrong count. Opus's competence removed the loud-error safety net that the weaker models accidentally provided.
- The **only never-silent arms are the deterministic and the curated** ones: OBDA (formal OWL2QL rewrite) is correct-or-refuses, and the metrics layer is pre-built — both tier-invariant by construction.

**The durable claim:** safety on these questions comes from the *execution / verification layer* — a deterministic rewrite that refuses, a curated metric, a refusing engine — not from model capability; and raising capability on an LLM-authored structured-query path can make it **more** dangerous, by converting caught (loud) failures into uncaught (silent) ones. "Verify every compute path; do not assume a more capable model is a safer one."

## Lookup (A2 / A6 / A8) — and a documented confound

- **Text-to-SQL: correct 1.0 at every tier** (full table access, no retrieval — it finds the needle by SQL).
- **GraphRAG: silent 1.0 at every tier.** The needles are not in the retrieved context. This is **confounded** and is *not* a clean test of the v2 hybrid-retrieval fix: the A9 fix enlarged the asset population (WS10–WS28), which added retrieval noise that crowded the lookup needles out of the locked node budget. The confound reproduces identically at all three tiers, which confirms it is a **retrieval-under-noise** artifact, not model-dependent. The pre-registered prediction "hybrid retrieval clears 70%" is therefore **inconclusive here**, not cleanly falsified — it needs an isolated re-run of the lookup class on the un-enlarged corpus. (v2.1 will separate this.)
- **OBDA:** A2/A6 correct, A8 loud (out of its expressible fragment). **Metrics layer:** A2/A6/A8 all correct.

## A4 — excluded as ill-posed (a clean v1 confound kill)

A4's point-in-time anchor, derived from the NL like every other arm, lands on the privilege-escalation marker event → 45 active sessions; the v1 gold constant (`pit_point_ms`, 2.7h later, tied to no named chain stage) → 35. The question as worded does not determine a single gold, so A4 is **excluded from scoring and reported as a question-design finding**, which removes the v1 "OBDA-safe-on-A4" artifact (that win was the OBDA template being fed the literal gold constant).

## Falsifier adjudication (pre-registered)

- **Graph-structure value = NULL (confirmed).** The structured-graph-query arm scored 0 correct on the tail at every tier; it does not beat the metrics-layer (1 correct) or the flat control. The v1 null holds — the *graph* confers no correctness.
- **OBDA determinism-safety = SUPPORTED but NARROW.** Correct-or-refuses, never silent, on its OWL2QL-expressible set (A2, A6) — but that set is 2 of 8; the entire tail + A8 are outside OWL2QL (no aggregation/recursion). Safe, but it cannot answer the questions that matter.
- **The reframe's falsifier fired in an unexpected direction.** "Compute-over-graph beats probabilistic compute" fails (structured-graph-query never correct) — and the *capability-dependent silent flip* is the new, sharper result: the safety of a structured path is not intrinsic to being structured; it depends on whether the query is *deterministic/curated* (safe) or *LLM-authored* (unsafe, and increasingly silently so at higher capability).
